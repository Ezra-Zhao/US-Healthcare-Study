# 事先授权与互操作怎么管：CMS 事先授权最终规则 CMS-0057-F 与加州规则

> 个人学习笔记，不构成法律或医疗建议。具体时限与适用以当期联邦规则、加州法典与监管机构口径为准。全文不写药物剂量。依据：CMS Interoperability and Prior Authorization Final Rule（CMS-0057-F），2024 年 2 月 8 日刊于 89 Fed. Reg. 8758；加州《健康与安全法典》§1367.01 一带利用审查规则。

## 中文主文

事先授权（prior authorization）是美国就医里最让人头疼的一道门：检查、手术、药物还没做，保险先审一遍「有没有必要」。审得慢，治疗就拖；拒了不给理由，医生和患者连补什么材料都不知道。CMS 在 2024 年出的 CMS-0057-F，就是冲着这两件事去的——一边给事先授权定决定时限与拒绝理由，一边用互操作 API 把患者数据、提供者数据与授权流程本身搬到标准接口上。这篇把规则的主干讲清：管谁、管什么、两个生效台阶分别在哪一年，再接上加州自己的一套利用审查时限与双监管口径，最后把适用范围的边界划清，不夸大。

**先说这条规则是什么、从哪儿来。** CMS-0057-F 的全称是 Interoperability and Prior Authorization Final Rule，2024 年 2 月 8 日刊于《联邦公报》89 Fed. Reg. 8758。它不是凭空另起炉灶，而是接在 2020 年的互操作规则 CMS-9115-F 后面：9115-F 先立了患者访问 API 与提供者目录 API 的底子，要求患者能经第三方应用取回自己的理赔与临床数据；0057-F 在此之上扩围——把事先授权流程本身纳入标准化，把旧 API 的用途加深，再新增提供者访问、付款方对付款方等接口。一句话概括两条规则的关系：9115-F 解决「数据能不能拿出来」，0057-F 接着解决「数据能不能在授权与转诊的真实流程里用起来」。

**管谁：只管「受影响付款方」，这一圈要画准。** 本规则约束的是 CMS 监管下的特定付款方（impacted payers），主要包括：Medicare Advantage 组织、州 Medicaid 与 CHIP 计划（按管理式医疗等安排运行的部分）、以及在联邦运营交易所（Federally-facilitated Exchange，FFE）上发售合格健康计划（QHP）的发行人等。为什么先强调这个名单？因为美国的保险世界远比这一圈大：雇主自保计划、州交易所自营平台上的部分安排、不在上述范围内的纯商业产品，都不必然直接受这条规则约束。患者判断自己的事先授权受不受 0057-F 保护，第一步是先看自己的计划属于哪一类付款方，而不是默认全美所有保险一体适用。末段还会再收一次这个边界。

**第一台阶（2026 年 1 月 1 日起）：事先授权的流程义务。** 自 2026 年 1 月 1 日起，受影响付款方处理事先授权要守三条硬线。第一，决定时限分档：常规（非加急）事先授权请求，要在 7 个日历日内作出决定并通知提供者；加急请求——临床情形等不起的那一类——要在 72 小时内作出决定并通知。注意口径是「作出决定并通知」，不是保险内部审完就算数；而且这是联邦底线，州法或计划合同另有更短时限的，从其更严者。第二，拒绝必须给具体理由：否决一项事先授权时，付款方须说明这项服务被拒的具体原因，让提供者知道是缺哪份病历、哪条临床标准没满足，而不是只收到一句模板式的「不符合医疗必要性」。这一条直接对应申诉与补件的实务：理由具体，才补得对、告得准。第三，公开统计：受影响付款方须按规则要求公开事先授权的统计数据——如批准、拒绝、申诉与改判等汇总口径，让外界能看见各付款方的授权行为模式。这一条的牙齿不在罚谁，而在透明：数据公开之后，异常高的拒绝率自己会说话。

**第二台阶（2027 年 1 月 1 日起）：五类 API 的互操作义务。** 自 2027 年 1 月 1 日起，受影响付款方要上线并维护一组基于 HL7 FHIR 标准的 API。逐个说清用途：Patient Access API（患者访问 API），患者经自己选的第三方应用取回理赔、临床与事先授权相关信息，是 9115-F 已有义务的延续与扩围；Provider Access API（提供者访问 API），经治提供者在治疗关系内取回其患者的数据，省掉靠传真与电话追病历的老路；Provider Directory API（提供者目录 API），把网络内提供者目录做成机器可读接口，让「这个医生到底在不在网内」能被应用直接查询；Prior Authorization API（事先授权 API），把某项服务要不要事先授权、需要交哪些文件、授权请求与决定状态，全部做成可机读、可提交、可查询的标准接口——这是本规则最有分量的一件新工具，目标是让授权从「打电话加传真」变成系统对系统；Payer-to-Payer API（付款方对付款方 API），患者换计划时，经本人触发，把既往数据从旧付款方转到新付款方，让病史与授权记录不因换保险而断档。五类 API 的共同点是都按 FHIR 标准建设，具体技术规范、实施指南与例外情形以 CMS 当期口径为准。

**两个台阶之间，还有一条容易漏的线：数据要跟着人走。** 0057-F 的整体逻辑，是把「事先授权改革」与「数据可携带」绑在一起：授权审得快不快，取决于临床资料到得全不全；Provider Access 与 Payer-to-Payer 两类接口补的正是资料这一环。所以看这条规则，不能只盯 7 天与 72 小时两个数字；数字是结果，接口才是让结果能稳定达成的手段。对患者一侧的实际意义是：换医生、换计划时，自己经 Patient Access API 取回并授权转移数据的权利，是可以主动行使的，不是只能等机构之间慢慢传。

**加州口径：州法另有一套利用审查时限与双监管。** 联邦规则之外，加州的健康计划还受州法约束。受 Knox-Keene 法管辖的健康计划，其利用审查（utilization review）时限写在《健康与安全法典》§1367.01 一带：对事先授权类请求按常规与加急分档设决定时限，并对逾期未决、拒绝通知与同行评审等环节有配套要求——具体时限与适用细节以当期法典条文与加州管理式医疗保健部（DMHC）口径为准，本文不凭记忆写死小时数，使用者务必回法典原文核对当期版本。要分清加州的双监管分工：DMHC 管健康计划（health care service plans，多数 HMO 与部分 PPO 属之），加州保险部（CDI）管保险公司发行的保单；同一件授权争议，先看自己的计划归哪家管，再找对应的申诉与独立审查通道走错门。另外记住衔接关系：一个加州计划如果同时是受影响付款方（例如 Medicare Advantage），联邦 0057-F 与州法可能在不同事项上分别适用，哪个问题走哪套规则，按计划类型与争议事项逐项判断，不是一句「联邦优先」能打发的。

**边界收尾：这条规则不管什么。** 把适用范围说过头，是读 0057-F 最常见的错误。第一，它管的是受影响付款方的事先授权与数据接口义务，不直接管临床决定本身对错——医生该不该开这项检查，仍是临床判断与计划医学政策的问题，规则管的是审的程序：时限、理由、透明与接口。第二，它不直接覆盖一切支付场景：患者全自付的服务、以及不在受影响付款方名单内的纯商业安排等场景，不因这条规则自动获得 7 日／72 小时的联邦时限保护，这类争议要回到州法、计划合同与申诉程序里找依据。第三，时限义务的起点是付款方收到请求，材料严重不全时流程如何计时、补件后如何续计，按规则文本与计划口径处理，患者一侧的实务动作始终是：提交时一次交齐、留好提交凭证、临近时限主动追踪。把这三条边界记住，才不会拿着一条好规则，用错地方。

*个人学习笔记，不构成法律或医疗建议。来源框架：CMS-0057-F（89 Fed. Reg. 8758，2024-02-08）关于受影响付款方、2026 年事先授权时限与拒绝理由及公开统计义务、2027 年五类 FHIR API 义务的规则文本；CMS-9115-F（2020）互操作规则的承接口径；加州《健康与安全法典》§1367.01 一带与 DMHC、CDI 分工的一般框架。急症拨打 911。*

## English

Prior authorization is the gate where care waits on an insurer's judgement of necessity, and CMS-0057-F — the Interoperability and Prior Authorization Final Rule, published on February 8, 2024 at 89 Fed. Reg. 8758 — was written to discipline that gate. It builds on the 2020 interoperability rule CMS-9115-F, which first required a Patient Access API and a Provider Directory API: 9115-F asked whether data could come out at all; 0057-F asks whether data can actually be used inside authorization and referral workflows. Scope comes first. The rule binds specific "impacted payers" under CMS oversight — principally Medicare Advantage organizations, state Medicaid and CHIP arrangements including managed care, and issuers of Qualified Health Plans on the Federally-facilitated Exchange — not every insurer or self-funded employer plan in the country. From January 1, 2026, three process duties apply to prior authorization by those payers: a standard request must be decided, with notice to the provider, within 7 calendar days; an expedited request within 72 hours; a denial must give the specific reason for that denial, so the provider knows which record is missing or which clinical criterion was unmet; and payers must publicly report prior authorization metrics on approvals, denials, appeals and overturns. From January 1, 2027, the interoperability duties arrive: five FHIR-based APIs — the Patient Access API (patients retrieve claims, clinical and prior-authorization information through an app of their choice), the Provider Access API (treating providers retrieve their patients' data within a treatment relationship), the Provider Directory API (machine-readable network directories), the Prior Authorization API (machine-readable rules on whether authorization is required, what documentation is needed, and the status of requests and decisions), and the Payer-to-Payer API (when a patient switches plans, data follows them from the old payer to the new one). California adds its own layer: utilization review by Knox-Keene health plans is governed by the timelines in and around Health and Safety Code §1367.01, with standard and expedited tracks — check the current code text and DMHC guidance for the operative figures rather than relying on memory. California regulation is split: the DMHC regulates health care service plans, while the California Department of Insurance regulates insurer-issued policies, and a dispute must be routed to the right regulator. Finally, the boundaries. The rule governs process — timelines, reasons, transparency and interfaces — not whether a clinical decision itself was right. It does not directly give every self-pay service or every purely commercial arrangement outside the impacted-payer list a federal 7-day or 72-hour guarantee; those disputes live in state law, plan contracts and appeal procedures. Authorization reform and data portability are deliberately bound together in this rule: decisions can only be fast and fair if the clinical record actually arrives. *Personal study notes only; not legal or medical advice. In an emergency, call 911.*

## Español (traducción de estudio)

La autorización previa es la puerta donde la atención espera el juicio de necesidad de una aseguradora, y la norma CMS-0057-F —Interoperability and Prior Authorization Final Rule, publicada el 8 de febrero de 2024 en 89 Fed. Reg. 8758— se escribió para disciplinar esa puerta. Se apoya en la norma de interoperabilidad de 2020, CMS-9115-F, que ya exigía una API de acceso del paciente y una API de directorio de proveedores: 9115-F preguntaba si los datos podían salir; 0057-F pregunta si los datos pueden usarse de verdad dentro de los flujos de autorización y derivación. Primero, el alcance. La norma obliga a «pagadores afectados» concretos bajo supervisión de CMS —principalmente organizaciones Medicare Advantage, los programas estatales Medicaid y CHIP incluidas sus formas de atención administrada, y los emisores de planes de salud calificados (QHP) en el mercado federal (FFE)—, no a todas las aseguradoras ni a todos los planes autofinanciados de empleador del país. Desde el 1 de enero de 2026 rigen tres deberes de proceso para la autorización previa de esos pagadores: una solicitud estándar debe decidirse, con aviso al proveedor, en 7 días naturales; una solicitud urgente, en 72 horas; toda denegación debe dar la razón específica, para que el proveedor sepa qué documento falta o qué criterio clínico no se cumplió; y los pagadores deben publicar estadísticas de autorización previa sobre aprobaciones, denegaciones, apelaciones y revocaciones. Desde el 1 de enero de 2027 llegan los deberes de interoperabilidad: cinco API basadas en FHIR —Patient Access API (el paciente recupera datos de reclamaciones, clínicos y de autorización mediante la aplicación que elija), Provider Access API (el proveedor tratante recupera los datos de sus pacientes dentro de la relación de tratamiento), Provider Directory API (directorios de red legibles por máquinas), Prior Authorization API (reglas legibles por máquinas sobre si una autorización hace falta, qué documentación se exige y en qué estado está cada solicitud y decisión) y Payer-to-Payer API (cuando el paciente cambia de plan, los datos lo siguen del pagador antiguo al nuevo). California añade su propia capa: la revisión de utilización de los planes Knox-Keene se rige por los plazos del §1367.01 del Código de Salud y Seguridad y su entorno, con vía estándar y vía urgente; verifique el texto vigente del código y la orientación del DMHC en lugar de fiarse de la memoria para las cifras operativas. La regulación californiana está dividida: el DMHC regula los planes de servicios de salud y el Departamento de Seguros de California (CDI) regula las pólizas emitidas por aseguradoras, y cada disputa debe ir al regulador correcto. Por último, los límites. La norma gobierna el proceso —plazos, motivos, transparencia e interfaces—, no si una decisión clínica en sí era acertada. No otorga directamente a todo servicio de pago directo ni a todo arreglo puramente comercial fuera de la lista de pagadores afectados una garantía federal de 7 días o 72 horas; esas disputas viven en la ley estatal, el contrato del plan y los procedimientos de apelación. Reforma de la autorización y portabilidad de datos van deliberadamente unidas en esta norma: las decisiones solo pueden ser rápidas y justas si la historia clínica llega de verdad. *Notas personales de estudio; no constituye asesoría legal ni médica. En una emergencia, llame al 911.*

## 한국어 (초역, 원어민 감수 대기)

사전 승인은 진료가 보험사의 필요성 판단을 기다리는 관문이며, CMS-0057-F(Interoperability and Prior Authorization Final Rule, 2024년 2월 8일 89 Fed. Reg. 8758에 게재)는 바로 그 관문을 규율하려고 나왔습니다. 이 규칙은 2020년 상호운용성 규칙 CMS-9115-F 위에 서 있습니다. 9115-F가 환자 접근 API와 제공자 디렉터리 API를 먼저 요구해 '데이터가 밖으로 나올 수 있는가'를 물었다면, 0057-F는 '그 데이터가 승인과 의뢰의 실제 흐름 안에서 쓰일 수 있는가'를 묻습니다. 범위를 먼저 못 박으세요. 이 규칙이 묶는 것은 CMS 감독 아래의 특정 '영향을 받는 지불자(impacted payers)'로, 주로 Medicare Advantage 조직, 관리형 의료를 포함한 주 Medicaid 및 CHIP 프로그램, 연방 운영 거래소(FFE)의 적격 건강보험(QHP) 발행인 등입니다. 미국의 모든 보험사나 고용주 자가보험 플랜이 아닙니다. 2026년 1월 1일부터 이 지불자들의 사전 승인에는 세 가지 절차 의무가 붙습니다. 일반 요청은 제공자에게 통지까지 포함해 역일 7일 안에 결정하고, 긴급 요청은 72시간 안에 결정합니다. 거절할 때는 그 거절의 구체적인 이유를 밝혀 제공자가 어떤 기록이 부족한지, 어떤 임상 기준을 못 채웠는지 알 수 있게 해야 합니다. 그리고 지불자는 승인·거절·이의신청·번복에 관한 사전 승인 통계를 공개해야 합니다. 2027년 1월 1일부터는 상호운용성 의무가 옵니다. FHIR 기반 API 다섯 가지입니다. Patient Access API는 환자가 자신이 고른 앱으로 청구·임상·사전 승인 정보를 가져오는 통로이고, Provider Access API는 치료 관계 안의 제공자가 자기 환자의 데이터를 가져오는 통로이며, Provider Directory API는 네트워크 제공자 목록을 기계가 읽을 수 있게 하고, Prior Authorization API는 승인이 필요한지, 어떤 서류가 필요한지, 요청과 결정이 어떤 상태인지를 기계가 읽고 제출하고 조회할 수 있게 하며, Payer-to-Payer API는 환자가 플랜을 바꿀 때 본인 촉발로 이전 지불자에서 새 지불자로 데이터가 따라가게 합니다. 캘리포니아는 자기 층을 더합니다. Knox-Keene 건강 플랜의 이용 심사(utilization review)는 《건강 및 안전 법전》 §1367.01 일대의 시한 규정을 따르며 일반과 긴급으로 나뉩니다. 구체적인 수치는 기억에 의존하지 말고 현행 법전 원문과 DMHC 기준으로 확인하십시오. 캘리포니아 규제는 둘로 갈립니다. DMHC가 건강 플랜을, 캘리포니아 보험부(CDI)가 보험사 발행 보험증권을 감독하므로, 분쟁은 맞는 감독기관으로 가야 합니다. 마지막으로 경계입니다. 이 규칙이 다스리는 것은 절차, 즉 시한과 이유, 투명성과 인터페이스이며, 임상 결정 자체가 옳았는지는 아닙니다. 영향을 받는 지불자 명단 밖에 있는 전액 자비 서비스나 순수 상업적 arrangement 전부에 연방의 7일·72시간 보장이 자동으로 생기는 것도 아니며, 그런 분쟁은 주법과 플랜 계약, 이의신청 절차 안에서 근거를 찾습니다. 이 규칙에서 승인 개혁과 데이터 이동성은 의도적으로 묶여 있습니다. 임상 기록이 실제로 도착해야 결정이 빠르고 공정할 수 있기 때문입니다. *개인 학습 노트이며 법률·의료 자문이 아닙니다. 응급 시 911에 전화하십시오.*

## Tiếng Việt (bản dịch sơ bộ, chờ hiệu đính)

Phê duyệt trước là cánh cổng nơi việc điều trị phải chờ phán quyết về nhu cầu y khoa của bên bảo hiểm, và CMS-0057-F — Quy tắc cuối cùng về Khả năng tương tác và Phê duyệt trước, đăng ngày 8 tháng 2 năm 2024 tại 89 Fed. Reg. 8758 — ra đời để kỷ luật cánh cổng đó. Nó đứng trên nền quy tắc tương tác năm 2020 CMS-9115-F, vốn đã yêu cầu API truy cập của bệnh nhân và API danh mục nhà cung cấp: 9115-F hỏi dữ liệu có lấy ra được không; 0057-F hỏi dữ liệu có thực sự dùng được trong quy trình phê duyệt và chuyển tuyến không. Trước hết là phạm vi. Quy tắc này ràng buộc các "bên chi trả bị ảnh hưởng" cụ thể dưới giám sát của CMS — chủ yếu là các tổ chức Medicare Advantage, chương trình Medicaid và CHIP của tiểu bang bao gồm hình thức chăm sóc có quản lý, và các nhà phát hành chương trình sức khỏe đủ điều kiện (QHP) trên sàn giao dịch liên bang (FFE) — chứ không phải mọi công ty bảo hiểm hay mọi chương trình tự bảo hiểm của chủ lao động trong nước. Từ ngày 1 tháng 1 năm 2026, ba nghĩa vụ quy trình áp dụng cho phê duyệt trước của các bên đó: yêu cầu thường phải được quyết định, kèm thông báo cho nhà cung cấp, trong 7 ngày lịch; yêu cầu khẩn cấp trong 72 giờ; mọi từ chối phải nêu lý do cụ thể, để nhà cung cấp biết thiếu hồ sơ nào hay chưa đạt tiêu chí lâm sàng nào; và bên chi trả phải công khai thống kê phê duyệt trước về chấp thuận, từ chối, khiếu nại và lật lại quyết định. Từ ngày 1 tháng 1 năm 2027 là các nghĩa vụ tương tác: năm API dựa trên FHIR — Patient Access API (bệnh nhân lấy dữ liệu yêu cầu bồi thường, lâm sàng và phê duyệt trước qua ứng dụng tự chọn), Provider Access API (nhà cung cấp điều trị lấy dữ liệu của bệnh nhân trong quan hệ điều trị), Provider Directory API (danh mục mạng lưới ở dạng máy đọc được), Prior Authorization API (quy tắc dạng máy đọc được về việc có cần phê duyệt không, cần giấy tờ gì, và trạng thái của từng yêu cầu và quyết định), và Payer-to-Payer API (khi bệnh nhân đổi chương trình, dữ liệu đi theo từ bên chi trả cũ sang bên mới). California thêm lớp riêng: thẩm định sử dụng (utilization review) của các chương trình Knox-Keene chịu thời hạn trong và quanh §1367.01 của Bộ luật Sức khỏe và An toàn, chia đường thường và đường khẩn; hãy kiểm tra văn bản luật hiện hành và hướng dẫn của DMHC để lấy con số đang áp dụng, đừng dựa vào trí nhớ. Giám sát ở California chia đôi: DMHC quản các chương trình dịch vụ chăm sóc sức khỏe, Sở Bảo hiểm California (CDI) quản các hợp đồng do công ty bảo hiểm phát hành, và tranh chấp phải đi đúng cơ quan. Cuối cùng là ranh giới. Quy tắc này quản quy trình — thời hạn, lý do, minh bạch và giao diện — chứ không quản việc một quyết định lâm sàng tự nó đúng hay sai. Nó không trực tiếp trao cho mọi dịch vụ tự trả hay mọi arrangement thương mại thuần túy ngoài danh sách bên chi trả bị ảnh hưởng một bảo đảm liên bang 7 ngày hay 72 giờ; những tranh chấp đó sống trong luật tiểu bang, hợp đồng chương trình và thủ tục khiếu nại. Cải cách phê duyệt và khả năng mang theo dữ liệu được buộc chặt với nhau trong quy tắc này một cách có chủ ý: quyết định chỉ nhanh và công bằng được khi hồ sơ lâm sàng thực sự đến nơi. *Ghi chú học tập cá nhân, không phải tư vấn pháp lý hay y tế. Khi khẩn cấp, gọi 911.*

## हिन्दी (प्रारंभिक अनुवाद, समीक्षा लंबित)

Prior authorization वह द्वार है जहाँ उपचार बीमाकर्ता के आवश्यकता-निर्णय की प्रतीक्षा करता है, और CMS-0057-F — Interoperability and Prior Authorization Final Rule, 8 फ़रवरी 2024 को 89 Fed. Reg. 8758 पर प्रकाशित — उसी द्वार को अनुशासित करने के लिए लिखा गया। यह 2020 के interoperability नियम CMS-9115-F पर खड़ा है, जिसने पहले Patient Access API और Provider Directory API अनिवार्य किए थे: 9115-F ने पूछा कि क्या डेटा बाहर आ सकता है; 0057-F पूछता है कि क्या डेटा authorization और referral के वास्तविक प्रवाह में सचमुच उपयोग हो सकता है। पहले दायरा स्पष्ट करें। यह नियम CMS की निगरानी में आने वाले विशिष्ट "impacted payers" को बाँधता है — मुख्यतः Medicare Advantage संगठन, managed care समेत राज्य Medicaid और CHIP व्यवस्थाएँ, तथा Federally-facilitated Exchange (FFE) पर Qualified Health Plan (QHP) जारी करने वाले — देश की हर बीमा company या हर self-funded employer plan को नहीं। 1 जनवरी 2026 से इन payers के prior authorization पर तीन प्रक्रियागत कर्तव्य लागू हैं: सामान्य अनुरोध पर provider को सूचना सहित 7 calendar दिनों के भीतर निर्णय; expedited अनुरोध पर 72 घंटों के भीतर; हर अस्वीकृति का विशिष्ट कारण देना होगा, ताकि provider जाने कि कौन-सा record छूटा या कौन-सा नैदानिक मानदंड पूरा नहीं हुआ; और payers को approvals, denials, appeals और overturns पर prior authorization आँकड़े सार्वजनिक रूप से प्रकाशित करने होंगे। 1 जनवरी 2027 से interoperability कर्तव्य आते हैं: FHIR-आधारित पाँच API — Patient Access API (रोगी अपने चुने app से claims, clinical और prior-authorization जानकारी प्राप्त करता है), Provider Access API (उपचार-संबंध के भीतर provider अपने रोगियों का डेटा प्राप्त करता है), Provider Directory API (मशीन-पठनीय network directory), Prior Authorization API (क्या authorization चाहिए, कौन-से दस्तावेज़ चाहिए, और अनुरोधों व निर्णयों की स्थिति — सब मशीन-पठनीय, प्रस्तुत-योग्य और खोज-योग्य), तथा Payer-to-Payer API (रोगी plan बदले तो डेटा पुराने payer से नए payer तक उसके साथ जाता है)। California अपनी परत जोड़ता है: Knox-Keene health plans की utilization review Health and Safety Code §1367.01 और उसके आसपास की समय-सीमाओं से चलती है, सामान्य और expedited मार्गों में — संचालन आँकड़ों के लिए स्मृति पर निर्भर न रहकर वर्तमान code पाठ और DMHC मार्गदर्शन जाँचें। California का नियमन दो में बँटा है: DMHC health care service plans को, और California Department of Insurance (CDI) insurer-जारी policies को नियंत्रित करता है, और विवाद को सही regulator के पास जाना चाहिए। अंत में सीमाएँ। यह नियम प्रक्रिया को शासित करता है — समय-सीमा, कारण, पारदर्शिता और interfaces — न कि यह कि कोई नैदानिक निर्णय स्वयं सही था या नहीं। यह impacted-payer सूची से बाहर की हर self-pay सेवा या हर पूरी तरह commercial व्यवस्था को संघीय 7-दिन या 72-घंटे की गारंटी सीधे नहीं देता; ऐसे विवाद राज्य-कानून, plan अनुबंध और appeal प्रक्रियाओं में रहते हैं। इस नियम में authorization सुधार और डेटा की portability जानबूझकर एक साथ बँधे हैं: निर्णय तभी तेज़ और न्यायसंगत हो सकते हैं जब clinical record सचमुच पहुँचे। *व्यक्तिगत अध्ययन नोट; कानूनी या चिकित्सा सलाह नहीं। आपात स्थिति में 911 पर कॉल करें।*
